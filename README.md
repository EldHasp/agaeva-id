# Агаева ID

Локальный помощник вкладки Битрикс24 на том же компьютере. Одна установка на компьютер. Служба Windows только будит программу в сессии вошедшего пользователя. Печать остаётся в этой сессии: служба сама не видит Chrome, Edge и Яндекс.Браузер рабочего стола.

Сейчас одно поручение: вкладка присылает HTML ответа ФССП, помощник печатает его установленным браузером и отдаёт PDF. Капчу помощник не решает и на сайт ФССП с данными человека не ходит. С сайта ФССП в момент печати берутся только общие таблицы стилей.

## Контракт вкладки

- `POST http://127.0.0.1:17321/print`
- тело: `{"html":"<фрагмент или страница ответа ФССП>"}`
- успех: байты PDF, `Content-Type: application/pdf`
- `OPTIONS` отвечает `Access-Control-Allow-Origin` и `Access-Control-Allow-Private-Network: true`
- ошибка: JSON `{"error":"..."}`, без поддельного PDF

Слушает только `127.0.0.1`. В журнал пишутся модуль, код и длительность. HTML, PDF и персональные данные туда не попадают.

## Как устроено

Служба стартует вместе с Windows и раз в несколько секунд проверяет активную консольную сессию. Если помощника в ней нет, служба запускает его от имени вошедшего пользователя на рабочем столе `winsta0\default`. Помощник принимает запрос вкладки и ищет модуль по пути. Модуль `print` готовит документ и печатает его. Следующие поручения вкладки добавляются такими же модулями рядом с `internal/modules/printmod`.

Печать идёт через протокол браузера: экранные стили, фоны, альбомный A4, обрезка по блоку результатов. Своя таблица вместо вёрстки ФССП не рисуется.

Программа написана на Go и собирается в один `agaeva-id.exe`. На компьютерах коллег не нужен ни .NET, ни Go. Локальная копия — обычное клонирование этого репозитория, каталог `apps/agaeva-id`. Отдельное решение Visual Studio не заводится.

## Установка на Windows

Один раз от администратора:

```text
agaeva-id.exe --install
```

Копия лежит в `C:\ProgramData\AgaevaId\`. Служба `AgaevaId` стоит в автозапуске Windows и после сбоя поднимается снова. Папка Startup и ключ Run не используются. Повторный вход не поднимает вторую копию в той же сессии.

Удаление от администратора: `agaeva-id.exe --uninstall`.

Сборка архива для релиза `AgaevaId-win-x64.zip` (внутри `agaeva-id.exe`):

```text
go build -ldflags "-X main.version=0.1.0" -o agaeva-id.exe ./cmd/agaeva-id
```

Переменные окружения `GOOS=windows` и `GOARCH=amd64` задают цель Windows.

## Самообновление

Пока программой пользуется один разработчик, самообновление выключено. `--install` создаёт `C:\ProgramData\AgaevaId\update.json` с `"enabled": false` и к релизам не обращается.

Когда копию отдают другим, на каждом таком компьютере один раз включают слежение:

```text
agaeva-id.exe --enable-update
```

После этого помощник в сессии пользователя раз в несколько часов смотрит публичные выпуски `EldHasp/agaeva-id-releases`. Токен на компьютер не передаётся: исходники остаются в закрытом репозитории, а для версий публикуется только архив. Если метка новее и к выпуску приложен `AgaevaId-win-x64.zip` с `agaeva-id.exe` внутри, программа останавливает службу, подменяет файл и снова её запускает. Служба будит уже новую копию. Выключить: `agaeva-id.exe --disable-update`. Повторная установка уже включённый переключатель не сбрасывает.

Репозиторий версий создаётся отдельно и должен быть публичным. Пока его нет, включённое самообновление просто пропускает проверку.

Программа лежит в этом репозитории, в `apps/agaeva-id`, потому что помощник относится к тем же локальным поручениям вкладки, а отдельный репозиторий здесь не заводился. Если помощник разрастётся, каталог можно вынести целиком.
